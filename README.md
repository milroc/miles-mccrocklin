# miles-mccrocklin

Personal site. Bun + React, deployed to GitHub Pages at [miles.mccrockl.in](https://miles.mccrockl.in).

## Scripts

```sh
bun dev                       # local dev server on http://127.0.0.1:4317
bun run build                 # production build → dist/
bun run typecheck             # tsc --noEmit
bun run build:world-countries # regenerate the explorer-page country polygons
```

## Data pipelines

### Country polygons — two ship targets, one source

The globe component (`src/splash/Globe.tsx`) renders in two contexts:

| File | Used by | Wire size | Vertex count | When it ships |
|---|---|---:|---:|---|
| `data/world-countries-50m.topo.json` | `/explorer/` (fullscreen globe) | ~97 KB gz | ~49 K | Deliberate user click, full coastline detail |
| `data/world-countries-tile.topo.json` | splash globe tile (~240 px square) | ~25 KB gz | ~6.5 K | First paint, aggressive simplification |

Both files are generated by `scripts/build-world-countries.ts` from the same Mike Bostock [`world-atlas`](https://github.com/topojson/world-atlas) source (Natural Earth 1:50m, plus 1:110m for Antarctica only). Run `bun run build:world-countries` to regenerate both. The TILE variant is ~3.9× smaller on the wire because the splash tile is small enough that 1° lat ≈ 0.4 px — sub-degree coastline detail is invisible at that scale and was just first-paint bloat.

**Why TopoJSON, not GeoJSON.** Adjacent country borders share *arcs* in TopoJSON instead of being expressed as independent coordinate sequences in each neighbor's polygon. That guarantees adjacent edges are byte-identical when decoded, eliminating the floating-point sliver gaps that the previous flat GeoJSON dataset showed at country borders. It's also much smaller on the wire — shared arcs aren't duplicated.

**Pipeline (`scripts/build-world-countries.ts`).**

1. Fetch the 50m TopoJSON from world-atlas.
2. Fetch the 110m TopoJSON, just to lift one cleaner Antarctica polygon out of it (50m fragments Antarctica into ~100 ice-shelf pieces; 110m has it as a single 554-vertex continent).
3. Decode both to GeoJSON, substitute Antarctica's geometry from 110m.
4. Remap 18 Natural Earth `NAME` short labels to the long forms the rest of the codebase uses (`Bahamas` → `The Bahamas`, `W. Sahara` → `Western Sahara`, …).
5. For each ship target (FULL & TILE), run the same pipeline with different settings:
   - Trim sub-polygons whose area is below the target's `trimRatio` of the country's largest polygon.
   - Re-encode to TopoJSON via `topojson-server.topology()` (un-quantized).
   - Run `topojson-simplify` (Visvalingam-Whyatt) at the target's `simplifyWeight` to drop sub-pixel vertices.
   - Quantize to a 10000×10000 grid via `topojson-client.quantize()` (also strips simplify's weight 3rd-dim).
6. Write both topologies, plus a GeoJSON sidecar (`data/world-countries-50m.json`, NOT shipped — used at build time by `scripts/timeline/build-journey.py`).

**Sizes.** GitHub Pages serves both files with `content-encoding: gzip` and edge-caches at Fastly with `max-age=600`. Decode in the browser is ~10–30 ms (FULL) / ~3–5 ms (TILE) via `topojson-client.feature()`. Globe.tsx kicks the fetch off at hydration in parallel with the splash reveal animation, so by the time the user clicks `/explorer/` the FULL dataset is usually already in HTTP cache.

**Size journey for FULL.** A snapshot of how the pipeline got here:

| Stage | Wire size | Note |
|---|---:|---|
| Original 110m flat GeoJSON | ~101 KB gz | Topology-broken: visible slivers at Kenya↔Somalia and dozens of other borders |
| 50m flat GeoJSON (re-derived from world-atlas TopoJSON) | ~575 KB gz | Topology fixed but expanded → shared arcs duplicated into both neighbors |
| + ship as TopoJSON, decode on client | ~230 KB gz | Each shared arc lives once instead of twice |
| + 10 000-grid quantization (`topojson-client.quantize`) | ~102 KB gz | Coordinates become small-integer deltas — gzip loves them |
| + Visvalingam simplify @ `1e-3` | ~97 KB gz | Drops sub-pixel triangles; topology preserved |
| + 0.1% island trim, Antarctica from 110m | ~97 KB gz | Same wire size, cleaner content |

End-to-end FULL is **~6× smaller on the wire than the same data shipped as expanded GeoJSON, with strictly better visual fidelity** (smooth coastlines, no border slivers, every photo country present, tiny outlying specks pruned). The TILE variant — same source, same pipeline, more aggressive `trimRatio` and `simplifyWeight` — drops a further ~3.9× to land at ~25 KB gz.

**Tunable levers in `scripts/build-world-countries.ts`.** The pipeline is parameterized by a `BuildOptions` object so we can call it twice. Two named configurations:

```ts
const FULL_BUILD: BuildOptions = {
  trimRatio:      0.001,  // keep Hawaii, Bermuda, Florida Keys, Canaries, Channel Is., …
  simplifyWeight: 1e-3,   // keep Norwegian fjords, Greek archipelago, ria coastlines
  quantization:   1e4,
};
const TILE_BUILD: BuildOptions = {
  trimRatio:      0.05,   // drop Hawaii, Tasmania, Sicily, Sardinia, Crete, Hokkaido
  simplifyWeight: 1e-1,   // drop every triangle below ~0.3° linear (~1 px at the tile)
  quantization:   1e4,
};
```

The simplification is **arc-level**, not feature-level. Adjacent country borders share an arc, and the simplifier processes each arc once — two neighbors always end up with byte-identical shared edges, so no new slivers are introduced regardless of how aggressive the simplification gets.

**FULL** (`world-countries-50m.topo.json`) is calibrated for "max coastline detail under 100 KB gz". Calibration data, sweeping the simplify weight at the FULL build's island ratio:

| weight | vertex retention | wire size |
|---|---:|---:|
| `2e-4` | 96 % | 112 KB gz (over budget) |
| `5e-4` | 87 % | 106 KB gz (over budget) |
| `1e-3` | 78 % | 97 KB gz (current) |
| `5e-3` | 47 % | 70 KB gz |
| `1e-2` | 36 % | 58 KB gz (visibly smoothed) |
| `5e-2` | 19 % | 38 KB gz (chunky / cartoon) |

**TILE** (`world-countries-tile.topo.json`) is calibrated for "clean continent silhouette at ~240 px tile size". Calibration data, sweeping the simplify weight at the TILE build's island ratio (`0.05`):

| weight | vertex retention | wire size |
|---|---:|---:|
| `5e-2` | 18 % | 30 KB gz |
| `1e-1` | 12 % | 25 KB gz (current) |
| `2e-1` | 8 %  | 21 KB gz (very chunky) |

Other levers:

- `quantization = 1e4` — snap coordinates to a 10 000 × 10 000 grid (~0.018° lat / ~0.036° lng = ~2 km / ~4 km at the equator). Matches world-atlas's source quantization. Quantized arcs are stored as small integer deltas (typically ±1..20), which gzip compresses extremely well — the dominant compaction step. Halving to `5e3` saves a couple of KB but doubles the worst-case position error; doubling to `2e4` adds ~5 KB on FULL.
- `COORD_DECIMALS = 4` — precision of the **sidecar GeoJSON only** (`data/world-countries-50m.json`, used by `scripts/timeline/build-journey.py` to compute country centroids). 4 decimals = ~11 m at the equator, way more than needed for a centroid. The shipped TopoJSON files' precision is governed by `quantization`, not this constant.

**Antarctica.** At 1:50m, Natural Earth fragments Antarctica into ~108 separate polygons (the continent itself plus every named ice shelf and offshore island) — none individually large enough to "look like Antarctica" once trimming runs. The build script fetches a second TopoJSON (1:110m) just to lift Antarctica's single-polygon representation out of it and substitute it into the 50m feature collection. Antarctica has no land neighbors, so the substitution doesn't break any shared borders. Result: one 554-vertex continent shape under the flat-photo shader instead of dozens of unrecognizable fragments.

**Verifying topology integrity after a regen.** Adjacent country borders should produce a non-zero number of byte-identical shared coordinates after `topojson-client.feature()` decodes the topology. Run this against either FULL or TILE:

```sh
bun -e '
  const FILE = process.env.FILE ?? "data/world-countries-50m.topo.json";
  const data = await Bun.file(FILE).json();
  const { feature } = await import("topojson-client");
  const fc = feature(data, data.objects.countries);
  const collect = (g) => new Set(
    (g.type === "MultiPolygon" ? g.coordinates.flat() : g.coordinates).flat().map(c => c.join(","))
  );
  for (const [a, b] of [["Kenya","Somalia"],["France","Germany"],["Argentina","Chile"],["United States of America","Canada"]]) {
    const fa = fc.features.find(f => f.properties.name === a);
    const fb = fc.features.find(f => f.properties.name === b);
    const sa = collect(fa.geometry);
    const shared = [...collect(fb.geometry)].filter(c => sa.has(c)).length;
    console.log(a, "↔", b, "shared:", shared);
  }
'
# Then re-run against TILE to check the small variant:
FILE=data/world-countries-tile.topo.json bun -e '…'
```

Each pair should print a non-zero number of shared vertices. Zeros mean the topology rebuild failed and slivers will appear at that border on the globe. Expect the TILE variant to have fewer shared vertices per border (more aggressive simplification dropped some), but never zero.
